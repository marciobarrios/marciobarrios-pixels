# Portfolio animation audit

Date: 2026-09-06. Commit: `b5fa76c`.

Scope: the home page and its interactive components. Read-only source audit using the improve-animations skill. Findings are awaiting selection; this file is not an implementation plan.

## Recon

- Stack: Next.js 16.3.4, React 19.2.8, Tailwind CSS 4, Base UI 1.8.0, tw-animate-css. No Motion, GSAP, or React Spring dependency.
- Motion lives in `src/app/globals.css`, Base UI wrapper classes, the rotating tagline's interval, and the portrait's WebGL drawing loop.
- Conventions: CSS transitions for interactive changes, CSS keyframes for entrances and tagline changes; several local cubic-beziers without shared motion tokens. The tagline uses a fixed prefix and a grid that reserves phrase width.
- Personality: a restrained personal portfolio with deliberate pixel-based playfulness. Marketing entrances and the pixel toy have room for longer timings.
- Frequency: page entrance once per navigation/reload; tagline every 3.6 seconds while visible; portrait, links, tooltip, and clip hovers several times per visit; work disclosure, video viewer, theme switch, and pixel toy occasionally. No high-frequency command palette or gesture-driven surface.

## Live evidence and limits

Inspected `https://marciobarrios-pixels.vercel.app/` in the Codex browser and performed a cache-bypassing reload. The four deployed reveal selectors match this checkout. After completion their computed styles still report `filter: blur(0px)` and `transform: matrix(1, 0, 0, 1, 0, 0)`.

One cold-reload timing sample, in milliseconds relative to navigation:

- Font response completed at 120.3ms.
- Stylesheet response completed at 138.1ms; the four entrance animations reported a start time of 133.3ms.
- Optimized initial portrait response completed at 138.6ms.
- First paint and first contentful paint occurred at 192ms.
- The portrait canvas's separate original-image request started at 203.6ms and finished at 244ms.

This sample does not support a late font download as the cause of the text effect. It does show that the canvas image arrives after first paint and during the 550ms identity entrance. Exact canvas readiness and a frame-by-frame recording were not obtained. The browser diagnostics available here did not support the attempted animation-event and early-document instrumentation methods. No unsupported diagnostic mutation succeeded or remains installed.

No source changes, installs, builds, formatters, commits, or E2E suite runs were performed. This checkout has no `node_modules`. Existing tests mostly inspect settled states, including waiting for reveal animations to finish before accessibility checks; they do not establish a clean first-paint sequence.

## Recommended next selection and verification

Prioritize #1 and #2 for the reload complaint, then #3 for the portrait's pointer behavior. #4 and #5 are separate motion polish tasks.

Implementation plans should require a production preview, normal and cache-bypassing reload recordings, cold-cache/throttled-network coverage, desktop Chromium and mobile Safari/WebKit, both color themes, reduced motion, and a no-JavaScript/WebGL fallback check. Scrub the first second frame by frame: text must not disappear after becoming legible or change its wrapping, and the portrait must not visibly switch from clear to pixelated without interaction. Verify the first tagline rotation happens after the page entrance and retains its reserved width. Test pointer movement around every portrait edge, rapid viewer open/close, and clip interactions on a real touch device.
